# ALIS — Learning Integrity Shield
Status: design; no detector integrated or benchmark validated.
## Pipeline
Authenticated source metadata → bounded quarantine → schema and provenance validation → deduplication and per-source contribution caps → statistical review → offline training → independent held-out evaluation → signed model registry → approved deployment and rollback. Never learn directly from production traffic.
## Candidate tools (version, license, compatibility and maintenance checks required)
- [IBM ART](https://github.com/trusted-ai/adversarial-robustness-toolbox): evaluate activation clustering, spectral signatures and provenance defenses for compatible classifiers; results are advisory. STRIP is a separate runtime detection candidate, not proof of a backdoor.
- [Cleanlab](https://github.com/cleanlab/cleanlab): label quality review with out-of-sample predictions.
- [Evidently](https://github.com/evidentlyai/evidently): distribution drift against frozen baselines; drift is not proof of poisoning.
- [BackdoorBox](https://github.com/THUYimingLi/BackdoorBox): literature review only; do not enable attack generation.
- [LLM Guard](https://github.com/protectai/llm-guard): candidate content screening; never treat screening as an authorization boundary.
- [Fickling](https://github.com/trailofbits/fickling): static inspection of pickle artifacts without deserialization; cannot certify safety.
- SafeTensors: prefer non-executable tensor serialization where compatible; verify provenance and resource bounds.
- DVC, MLflow, Sigstore: evaluate versioned manifests, restricted registry and signed releases.
## RAG integrity
Allowlisted authenticated sources, document-level ACL enforcement at retrieval and output, immutable version identifiers and hashes, quarantine unexpected changes, separate untrusted content from instructions, no tool authority from retrieved text. Revoke and reindex affected documents and derived embeddings. Never trust a document solely because a classifier accepts it.
## Acceptance
Synthetic fixtures only: duplicate handling, contribution caps, invalid provenance, drift vs legitimate change, unauthorized retrieval denial, unsigned artifact rejection, rollback and lineage completeness. Suspicious records quarantined, not auto-deleted. A 2% alert threshold is experimental only; calibrate with held-out data, confidence intervals and measured false positives. Critical deterministic invariants require zero failures; statistical non-inferiority gates predefined. No claim of immunity.
## Isolation
Python research workers offline with no production credentials; Rust runtime enforces deterministic permissions. No real secrets, live malware, executable untrusted artifacts or offensive generation. Review dependency licenses before distribution. Keep Windows alpha priority.

## AADP — Adaptive Drift Protection
Design only. Compare recent aggregate statistics with a separately approved frozen reference, using feature-specific absolute and relative tolerances; handle near-zero reference values and missing data explicitly. Quarantine unexplained drift, suspend candidate baseline promotion, and require reviewed evidence for any reference change. A bounded robust estimator may reduce the influence of anomalous observations in offline candidate training; it does not eliminate cumulative manipulation. Evaluate KS and distribution distance metrics with adequate sample sizes, seasonality, multiple-testing correction and independently calibrated thresholds. Use authenticated source contribution caps and deterministic operational quotas enforced independently of ML. Quotas must be scoped, atomic, auditable and fail closed for protected exports; exceptions require transaction-bound approval. Monitor legitimate workload changes and preserve recovery paths. Dashboard reports observed drift, sample coverage, policy version, uncertainty and review state without exposing secrets. Synthetic regression fixtures cover stable distributions, approved changes, unexplained drift, missing telemetry, zero reference, invalid configuration and quota enforcement. No production online weight updates; no offensive simulation or evasion generation. No universal numerical thresholds or claims of poisoning immunity. Windows alpha remains the first release priority.

## ACCC — Cryptographic chain of custody
Design, not implemented. Record authenticated source/batch IDs, capture time and trust status, digest of retained input bytes, schema and version; avoid retaining raw personal data unless necessary and lawful. Record each transformation with input/output digests, code/config/dependency versions, counts and quarantine reasons. Bind model digest to dataset manifest, training run, evaluation reports and approved release via signed in-toto-style attestation. Separate producer, reviewer and deployer identities; verify signatures, trust roots, artifact digest and approval scope before promotion. Use versioned canonical encoding and established crypto libraries; evaluate DVC/lakeFS, OpenLineage/Atlas, MLflow, Cosign, RFC3161 and WORM storage. Append-only sequence/hash links plus independently anchored signed checkpoints detect modification, deletion, truncation and forks within stated trust assumptions; hash chain alone cannot prove completeness. Key rotation, revocation, access control, encrypted backup, retention/deletion policy and offline verification required. No real telemetry, secrets or personal data in public GitHub or public transparency logs. Hashes and detector reports demonstrate integrity/check outcomes, not truth, absence of poisoning or legal admissibility. Audit export maps intended use, data governance, technical documentation, logging, risks, oversight, limitations and post-market monitoring to EU AI Act arts 10–15 and Annex IV where applicable; official consolidated text https://eur-lex.europa.eu/eli/reg/2024/1689 and Commission timeline https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai (checked 2026-11-24). Annex III rules apply 2027-12-02; Annex I 2028-08-02; classification depends on intended use. Italy Law 132/2025 art 20 distinguishes AgID notification and ACN market surveillance with sector exceptions. Tests: synthetic chain, altered bytes, missing links, truncated tail against external checkpoint, wrong signer, wrong model/dataset binding, revoked key, unauthorized promotion, rollback and privacy-safe export. No compliance certification claims. Preserve Windows alpha priority.

## ALIS-01 — bounded admission rehearsal (2026-11-25)
Implementation in src/lib.rs, commit b251e582. A pure Rust fixture classifier with no new dependencies; not wired into the CLI or any training/production pipeline. It evaluates a bounded batch (maximum 256), separately supplied source-to-group registry, mock verification status, schema version, nonzero synthetic digest, global deduplication of eligible records, per-source and per-group caps. An invalid configuration rejects the whole batch. A rejected record never consumes candidate quota or deduplication state. CandidateOnly means eligible for further review, never trusted, signed or approved for training.
Acceptance: eight unit test functions covering eligibility, unverified/unknown sources, schema/digest rejection, duplicates, source/group limits and independent groups, invalid configuration, empty/oversized/boundary batches and deterministic repeatability. Static self-review only; compilation and tests await CI. No independent reviewer or security validation. No actual authentication, digest calculation, persistence, quarantine storage, raw payloads, network, production data, training, or deployment. Quotas reset per batch and depend on input order: a real implementation requires authenticated identities, canonical encoding, verified manifests, atomic persistent quotas across time windows, protected registry and audited quarantine retention, drift checks and independent holdout before any learning. First-eligible ordering can bias selection; measure legitimate source coverage and use reviewed selection before training. Never promote a candidate on this result alone.

## ALIS-02 — frozen-reference aggregate comparison (2026-11-25)
ALIS-01's eight tests passed in CI 45546432359, with all three desktop jobs green. ALIS-02 (ca9a1a6) adds a pure synthetic binary-feature proportion comparison. A separately provided reference version and two aggregate windows are bounded to one million observations each. Minimum evidence and valid counts are mandatory; an exact rational absolute difference in parts per million avoids rounding and overflow, including zero reference. Equality at the configured threshold is within tolerance. The reference remains immutable; comparing each successive window to that same reference can flag cumulative change. Eight new unit test functions cover equal proportions, threshold boundaries and directions, zero reference, one-count difference, missing/insufficient evidence, malformed windows/configuration, maximum values and cumulative change. No automatic training or containment; WithinTolerance is not a finding of safety. The version number is not authenticated, no confidence intervals, seasonality, multivariate statistics, real telemetry, baseline persistence, source integrity or quarantine implemented. The 20,000 ppm fixture is not a calibrated deployment threshold. New CI pending at time of writing. Static self-review only.

## ALIS-03 — candidate evidence binding rehearsal (2026-11-25)
ALIS-02's eight synthetic drift tests passed on the Windows job in run 45553115784; all three desktop jobs succeeded. ALIS-03 (ef7b91f) is a pure offline fixture precheck: bind evaluation and review to exact model, training manifest, holdout manifest, frozen reference identifiers and policy version. Reject zero identifiers, stale policy, evidence mismatch, missing provenance/quarantine clearance, identical training/holdout manifest identifiers or missing split evidence, empty evaluation, any deterministic invariant failure, missing statistical gate, independent review or rollback evidence. Eight new test functions cover these cases. The only positive result is EligibleForExternalReviewOnly; no training or deployment authority. All evidence flags and identifiers are synthetic, not cryptographic verification, authentication or actual independent review. Different manifest digests alone cannot prove disjoint records or lack of leakage. Production requires canonical signed manifests, protected verifier trust roots and revocation, record-level split checks, independently managed holdout, replay-resistant transaction approval and atomic registry/rollback checks; no online learning. New tests await CI. Static self-review only.
